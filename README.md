## 실습 기록 제출

1. **계좌와 거래를 두 테이블로 나눈 이유 (1:N 관계)**
   계좌 하나에 거래가 여러 건이 생겨서, 거래마다 계좌 정보를 복사하지 않고 `account_id`(외래키)로 계좌를 가리키게 했다. 계좌 이름·잔액은 한 곳에서만 관리하고, 외래키 덕분에 존재하지 않는 계좌의 거래는 DB가 거부한다.

2. **SQLAlchemy 모델 클래스와 실제 테이블의 대응**
   `class Account(Base)` 하나가 `accounts` 테이블 하나가 되고, 클래스 속성(`name`, `balance`)이 컬럼, 객체 하나가 행 하나에 해당한다. `Base.metadata.create_all()`이 이 클래스 정의를 보고 `CREATE TABLE`을 대신 실행한다.

3. **접속 문자열을 `.env`로 분리하는 이유**
   연결 문자열에 DB 비밀번호가 들어 있어 코드에 직접 쓰면 GitHub에 그대로 공개된다. 그래서 `.env`에 두고 `.gitignore`로 제외했다. 로컬에서는 `.env`, Render에서는 환경변수로 같은 `DATABASE_URL`을 읽으므로 코드는 바꾸지 않아도 된다.
